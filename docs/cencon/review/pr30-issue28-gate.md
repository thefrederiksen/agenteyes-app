Blocking defects:

1. The CLI does not own the camera recorder through a failure boundary. `src/AgentEyes.Core/Commands.cs:297` stores it in a nullable local, `src/AgentEyes.Core/Commands.cs:313` can then throw while starting the screen recorder, and the only camera cleanup is the normal-path calls at `src/AgentEyes.Core/Commands.cs:342` and `src/AgentEyes.Core/Commands.cs:343`. Concrete failure scenario: the camera opens successfully, then gdigrab fails to open the screen (or `sysCap.Start`, `recorder.Stop`, audio processing, probing, or manifest saving throws). `Program.Main` reports the error and exits the command, but no `finally` or `using` stops/disposes `cameraRec`; its ffmpeg process can keep writing `camera.mp4`, hold the webcam open, and strand the new recording directory.

2. Camera stop can report success while ffmpeg is still running. `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:220` treats an 8-second timeout as a warning, `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:224` swallows a failed kill, and `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:225` ignores whether the second wait timed out. Because `_stopped` was already set at `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:200`, `Dispose` at `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:261` will not retry termination; disposing `Process` does not terminate the OS process. Concrete failure scenario: dshow is stuck and ffmpeg ignores `q`, then `Kill(true)` fails or ffmpeg remains alive after the second timeout. `Stop` returns normally, and `RecordingService` sets state to idle and releases the capture claim at `src/AgentEyes.Core/RecordingService.cs:584` through `src/AgentEyes.Core/RecordingService.cs:606` while ffmpeg still owns the webcam and output file.

3. The 400 ms startup probe does not establish that the camera opened. `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:160` waits a fixed interval and rejects only a process that has already exited with a non-zero code; every still-running process, and even one that exited with code 0, is marked opened at `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:185`. Concrete failure scenario: a busy, unplugged, or unsupported DirectShow device takes more than 400 ms to fail. The method returns success, the screen recorder starts, and the later camera exit is treated as a non-fatal mid-run loss, so a camera that never produced a usable track silently becomes a screen-only recording instead of failing the start as AC9 requires. If ffmpeg exits with code 0 during the probe, the `Exited` handler ignores it because `_opened` is still false and no later event marks the track lost.

4. A real mid-run loss can be recorded as a clean camera track. `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:199` sets `_stopped` before observing whether the process already exited; the `Exited` handler returns when it sees `_stopped` at `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:146`. The local `lost` value computed at `src/AgentEyes.Core/Video/FfmpegCameraRecorder.cs:202` is used only for a log line and is never assigned to `_lostMidRun`, while the manifest reads `camera.LostMidRun` at `src/AgentEyes.Core/RecordingService.cs:527`. Concrete failure scenario: the camera process dies immediately before the user stops, with its exit callback not yet delivered. `Stop` suppresses the callback, observes `HasExited`, then returns with `LostMidRun == false`; the manifest writes `CameraTruncated: false` and the required warning is omitted even though the camera file ended early.

5. The Devices API adds a forbidden fallback that makes broken enumeration indistinguishable from no camera. `src/AgentEyes.App/RestServer.cs:399` through `src/AgentEyes.App/RestServer.cs:403` catches every camera-enumeration exception and returns `cameras = []` with HTTP 200. Concrete failure scenario: ffmpeg is missing, cannot start, or device enumeration throws; callers are told that the machine has no cameras and receive no actionable failure, violating the repository's no-fallback standard and making AC1's empty-array meaning false.
