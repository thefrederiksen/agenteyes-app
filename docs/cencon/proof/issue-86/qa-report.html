6. QA observations (not defects; recorded for honesty)

  • App.OnExit disposes the quit listener inside try { ... } catch { } - an empty catch, matching the two pre-existing lines beside it (_captureRegionHook, _captureFullHook). Consistent with its surroundings; a log line there would be better. Not this issue's scope.
  • UpdateRunner.RecordInstalledVersions logs and swallows a bookkeeping failure ("best-effort") - pre-existing design, carried over unchanged.
  • RunningAppHandle.Find with more than one AgentEyesApp process relaunches the first and stops all; logged. The single-instance lock makes this the rare case.
  • WizardInstallRunnerTests write one setup log file per run under %LOCALAPPDATA%\AgentEyes\logs\setup\ (disclosed in the handoff); AlwaysOnRestartTests encode one 2 s template MP4 with ffmpeg per run. Both run inside dotnet test; no AgentEyes binary is started. The full suite takes ~45 s, not the ~2 s the project instructions quote - pre-existing growth (1984 tests on main), not this PR.
  • The first update FROM a 1.11.x build is force-stopped after the legacy 3 s (no listener) and its clip is recovered as from a crash that one time; the developer flags this as assumption 7 and the tester's step 3 expects it.
