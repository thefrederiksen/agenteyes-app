Review notes (non-blocking)

  • The tooltip drops today's totals while keeping (both do not fit in 127 chars); a long clips folder gets cut with "...". Acceptable for "short form".
  • OpenClipStart before the first keeper decision uses the oldest waiting piece - an approximation within one piece length; the display is in whole minutes.
  • UnlistedNote and the AOClipRow binding have no unit test (private UI code); covered by review only.

Limits - what was NOT exercised live

The installed v1.11.0 AgentEyesApp (running from %LOCALAPPDATA%\AgentEyes\app, always-on to C:\AgentEyes) holds the global single-instance mutex, port 7882 and the shared config, and QA was instructed not to stop or disturb it. A second instance of the new build cannot run beside it, and no harness exists that hosts the Always On page in isolation. Therefore the page line, the clip list rendering, click-to-reveal in Explorer, the tray tooltip, and the new GET /always-on fields were NOT exercised in a running app. They are judged by code review plus the unit tests above (with mutation evidence). The only live action was a read-only GET /always-on against the installed v1.11.0 instance (state "off", ClipsToday 3, no new fields - as expected for the old build) and a read of its today.json, used to confirm the upgrade-day counted-but-not-listed behaviour.
