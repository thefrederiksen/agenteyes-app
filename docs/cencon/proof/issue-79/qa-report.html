5. Review findings by QA (non-blocking; recorded so they are not lost)

  1. Shared-log read race widened. Log.Write swallows the IOException when another thread holds the log open for reading (section 1). Tests that read the run log with File.ReadAllText(Log.CurrentFile) (share mode Read) went from 1 on main to 4 on this branch (AlwaysOnAppTests.cs x1, AlwaysOnEngineTests.cs x3). Two flakes were seen across QA's eight full runs (four pristine, four mutated): the untouched RecordingStopSequenceTests case in pristine run 1, and this PR's own Engine_ClipIsTrimmedToItsSpan_... once under M4 (5/5 in isolation, green in the other seven full runs). No product code is wrong; the log-asserting tests are exposed to a race that already existed on main. Suggested follow-up issue: have test readers open the log with FileShare.ReadWrite | FileShare.Delete as RecordingStopSequenceTests.LogSince already does, or make the logger retry the append instead of swallowing. Not a criterion of #79.
  2. CameraPreviewTests timing cases failed once under M2 (not touched by this PR; green in all pristine runs). Same class of pre-existing flake; noted for the same follow-up.
  3. API contract change (openClip.afterMinutes -> openClip.silenceGapSeconds; status.KeepAfterMinutes -> three second-fields) is stated in the PR body and the handoff; no consumer in this repo reads the old names.
