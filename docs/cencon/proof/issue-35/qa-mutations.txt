WHAT NONE OF THIS CAN SEE
-------------------------
* CameraDeviceArbiter coordinates holders INSIDE one process. A recording started from the
  CLI (agenteyes.exe, its own process) while the tray app previews cannot be rescued by it;
  that path fails loudly with "already in use by another application". This is documented in
  CameraDeviceArbiter's own summary and is unchanged by this issue - not a #35 defect.
* The probe drives Save/Save as/Cancel through ReadInto/Validate and the region handlers, not
  by clicking the buttons: DialogResult can only be set on a window opened with ShowDialog,
  and opening one would steal the human's focus. What is verified instead is that ALL FIVE
  close routes (Save, Save as, Cancel, the X, Esc) funnel through Window.Closed -
  Save_Click / SaveAs_Click / Cancel_Click each end at `DialogResult = ...`, Esc reaches
  Cancel_Click via IsCancel="True" - and that Window.Closed releases the camera, observed at
  runtime (AC9 path 4) and mutated (M3).
