(.github/workflows/ci.yml:167-184), copied verbatim except that the output directory is an
argument so it can be aimed at a deliberately BAD build.

Three arms: good = exit 0 with the [OK] line; bad = exit 1 naming the word or the missing file;
an empty/absent output folder is caught by BAD 3 rather than passing silently.

=== One thing a Mac developer has to know, found while running the gate above ===
tests/AgentEyes.Tests.Linux references the desktop app pinned to AgentEyesUnixPlatform=linux,
and the mac and linux flavours share src/AgentEyes.DesktopApp/bin/Release/net8.0. So running
the macOS gate REPLACES the macOS app output with a Linux-flavoured one. Measured here, in
this order, in the same directory:
  after the gate run: {'x11grab': 1, 'pulse': 8, 'avfoundation': 0}
  after rebuilding mac: {'x11grab': 0, 'pulse': 0, 'avfoundation': 2}
  Launching bin/Release/net8.0/AgentEyesDesktop straight after the gate therefore starts an app
  carrying the X11/PulseAudio engine on a Mac. CI does not hit this (its macOS job never builds
  the Linux test project). It is not a criterion failure - it is a trap worth a note in the
  developer loop: rebuild the app after the gate, before you run it.
