Code review findings

  • SoundLog: the line is taken before the finished second joins the floor history (a second is judged against the room, not itself); MarkLoud checks every 10-s span that can contain the new second, so out-of-order seconds from two sources are handled; Prune clears both sets; LastSoundUtc now tracks sustained sound only. Logic matches the issue's decisions (RMS, 3-in-10, floor p20 + 15, min -50, same rule for a fixed line).
  • AudioCapture / LoopbackCapture: BufferLevel is an additional event; LevelChanged (meters, HUD) is unchanged. Normal-recording GateCalibration untouched, as scoped.
  • Logging present (SoundLog created line states the rule; once-per-minute levels line). No try/catch added in helpers. Diff is ASCII-only (byte scan 0 hits; control string fires).
  • Privacy posture unchanged (visible / controllable); the change keeps less, and makes the line and floor visible.

Observations (not defects against this issue's criteria)

  • Applying the new rule (-50 line, 3 in 10) to the WHOLE 5 h 51 min clip gives 1058 sustained-sound seconds; a 5/5-min keeper would still keep about 235 of 351 minutes, as several clips. That file is a MIXED recording (mic + system at 0.7), and today's live run shows system audio playing often on this laptop at -20..-25 dBFS, so those seconds are plausibly system audio that a counts=mic meter would not hear. Worth watching the first real day on the new build via the levels log.
  • With Auto, continuous system audio from the start raises the 10-min floor (seen live: system floor -27, line -12), so steady audio that was already playing does not count. This follows the issue's rule; flagging it for the owner.
  • Whether normal talking into the built-in Realtek mic reaches -50 dBFS RMS was not measured: the mic delivered ~-96 dBFS during QA, and no recording on disk was made with that mic while someone spoke.
