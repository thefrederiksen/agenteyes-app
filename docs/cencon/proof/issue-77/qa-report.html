7. Coding standards and CenCon review

  • Responsive UI: "Loading..." at once, Task.Run for the read and the row build, virtualized recycling ListBox (MainWindow.xaml:844). No sync I/O on the UI thread found in the new UI code.
  • UI thread safety: every ObservableCollection change goes through Dispatcher.BeginInvoke; the collection built off-thread is not bound until it is handed over on the UI thread.
  • Logging: MicEndpoint.Read/Find, AlwaysOnHistory.Count/Events/Load/Trim/Rewrite/Append, the engine's UpdateSilentMic/ApplyMicEndpoint/Stop(why), the route, and every tab handler log entry/result/failure with the [Class] Method: prefix.
  • No fallback programming: MicEndpoint.Select refuses an ambiguous or missing name with the candidates and the fix, never guesses; ParseFilter refuses an unknown kind (400), never "all"; a bad since is a 400. The history's own failures are logged and truthfully described (kept vs LOST) and, by design, never stop the recording - stated in the class remarks and the same rule #81 set for today.json.
  • Try-catch at entry points: the tab's handlers (AOTabs_SelectionChanged, AOHistoryFilter_Changed, the async void load, the dispatched insert) and the engine's Record boundary; the store catches only IOException/UnauthorizedAccessException at its file I/O with a logged reason.
  • Tests named Method_Scenario_Result, Arrange-Act-Assert; each test isolated on its own temp folder and its own history file; none touches the live history file.
  • Privacy posture: unchanged. The change adds visibility of what always-on did and of Windows' own mute/volume for the mic it already listens to; nothing new about the owner's content is captured. No component-map change.
  • Non-blocking observations (not defects against any criterion): (a) if the endpoint READ starts failing (device unplugged) while the capture is down and the prior verdict was Muted, UpdateSilentMic closes the silence with Windows no longer reports the microphone muted. - literally true, since Windows then reports nothing, and the separate "could not be read" warning is recorded beside it; (b) the trim tests derive their expectation from KeepFromUtc (section 5, mutation 3 note); (c) N = 10 min is a named constant and a stated assumption for the owner, as the review already noted.
