Review findings

  • No product behaviour change: the redirect is never called by product code (only TestRunIsolation calls RedirectForThisProcess).
  • Fail-closed ordering: a path resolved before the redirect makes the module initializer throw, failing every test rather than running against real folders.
  • Log format change: new shape HH:mm:ss.fff [pid N] [LEVEL] message; nothing in the repo parses the old shape (QA grep of src, tools, scripts, clients, plugins for [INFO]/[WARN]/[ERROR], Log.CurrentFile, Log.Dir: only path displays in App.xaml.cs/UpdateChecker.cs and SelfTest's work folder, no line parser).
  • Pruning of old run folders only deletes names that parse as run-yyyyMMdd-HHmmss-pid older than 2 days (enumerates what to delete).
  • Repo coding standards: ASCII only, logging on the new public entry points, no fallbacks added; try/catch in PruneOldRuns is narrow (IO/Unauthorized) and logged.
  • Non-blocking: the env-var scan does not cover the test assembly (documented limit).
