=================== C. Criterion 4: the app's NAME was wrong - found and fixed ===================
First install, before the fix:  lsappinfo info -only name com.agenteyes.app  ->  "LSDisplayName"="Avalonia Application"
Cause: Avalonia's Application.Name defaults to 'Avalonia Application' and it is what Avalonia gives macOS as the app's name, overriding CFBundleName. Fix: Name="AgentEyes" on <Application> in App.axaml.
After the fix (second install):  "LSDisplayName"="AgentEyes"
NOT OBSERVED, and why: the menu bar and the dock. The screen is locked and the frontmost app is loginwindow, so AgentEyes is never the active app. A capture of the menu bar window (Window Server window 26) shows ANOTHER app's menus (dev-menubar-while-locked.png - white text on a transparent strip). The Dock's window (id 7) is offscreen while locked and captures as a blank white 1920x1080 frame (not committed).

=================== I. The bundle's privacy identity (for the bundle-identifier decision) ===================
$ codesign -d -r- ~/Applications/AgentEyes.app -> designated => cdhash H"b2b257b5a9594d7f20784f2489bb1d899b83b200"
$ codesign -d -r- <installed service agenteyes> -> designated => cdhash H"0b2bc9d96c152a6858bafc7ae9a6b84a1b717ffb"
An ad-hoc identity IS the code hash. Rebuilt from the same source: CDHash=b2b257b5... (identical; dll and CodeResources seal cmp-identical).
Rebuilt with only <Version> 1.11.11 -> 1.11.12: CDHash=e18531401ac124de583f8dbf8f247684588cab38 (different).
The SERVICE, by contrast (re-measured today, as #114 section 3 did): a fresh self-contained publish of the engine from this branch vs the INSTALLED agenteyes (it reports 1.11.11+f9ef2306539007cbd0ef8cc3d2a746e8dd88dfab): apphost cmp IDENTICAL, designated => cdhash H"0b2bc9d96c152a6858bafc7ae9a6b84a1b717ffb" on both; only agenteyes.dll differs. So an update keeps the service's identity unless the apphost itself changes (another .NET SDK / apphost pack, an assembly rename).
So every RELEASE of an ad-hoc bundle is a new application to the privacy settings. The bundle's code hash covers Info.plist and the seal of all 657 files, unlike the service's bare apphost, whose hash does not change with the C# (#114).

=================== K. Signatures and extended attributes ===================

  after cp -R:                     codesign --verify --deep --strict -> OK
