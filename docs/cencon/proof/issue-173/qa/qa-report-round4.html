3. The .target reasoning - checked against the root zone, and it is the correct rule, not just the cautious one

Fetched https://data.iana.org/TLD/tlds-alpha-by-domain.txt, "Version 2026111700" (the version the docstring cites). systemd's unit types are exactly eleven: service, socket, device, mount, automount, swap, target, path, timer, slice, scope. Of these, only TARGET is delegated; the other ten are not. SERVICES (plural) is delegated, and the guard keeps it red.

So a blanket "unit-looking suffix" rule would have been wrong, not merely loose: a mailbox name, an at sign, then company.target is a syntactically valid address under a delegated TLD, and allowing all .target would have whitelisted it. The narrower rule (the ten undelegated types allowed with any instance; .target only with an all-digit instance, the per-user manager form) is the one that follows from the zone. Probes: named-instance .target RED, numeric-instance .target green, a .services address RED, a named .service/.timer instance green.

Two caveats, neither a defect: (a) the docstring says no mailbox domain can be an all-digit label under .target - all-digit labels are legal in DNS (RFC 1123), so this is "vanishingly unlikely on a single-registrant brand TLD", not "impossible"; (b) the ten-type allowance is dated to root zone 2026111700 - if ICANN ever delegates one of those strings, the allowance becomes a hole. Both are acceptable residual risk for a guard of this kind.
