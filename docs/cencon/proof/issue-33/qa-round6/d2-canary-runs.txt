All four runs below are the REAL app, driven focus-free through UI Automation (no synthesized
input, no force-foregrounding). The recording is started with the main window's REC button, which
is the only route that puts the HUD on screen (a REST /record/start does NOT create a HUD - measured
first, and that is why these runs do not use the API).

no UI Automation TransformPattern - i.e. the "fifth route" the allowlist in HudUserResize does not
recognise. It is the message shape the Review Gate named as reproducing the same state transition
as Windows keyboard snap / Snap Layouts.
